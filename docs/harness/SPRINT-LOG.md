## 회차 1 — 첫 실전 투입 (01:31~02:05)

**한 일**: `spec-analyst`를 `docs/03_지수로그함수_미분.md`에 실제로 투입 (opus, 74k 토큰, 3분 29초)

**결과**: 개념 9개(c13~c21) · 신규 팁 1개(`euler`) · 재사용 5개 · **표현불가 4개** · 에스컬레이션 6건

**검증된 것 — 회차 0의 두 예측이 실제로 맞았다**

1. **표현불가 에스컬레이션이 실제로 걸렸다.** `derivative`, `naturallog`, `chainrule`, `basechange` 4개가 산점도로 표현 불가 판정되어 파일이 생성되지 않았다. 특히 `naturallog`에 대한 에이전트의 근거가 정확하다 — *"ln n을 억지로 찍으면 발산하는 수열 그림이 되어 학생이 자연로그를 발산 개념으로 오각인한다."* **`build.py`는 이걸 절대 못 잡는다.** 형식만 보기 때문이다. 하네스가 실제로 값을 만든 지점.
2. **기존 자산 실독 규칙이 작동했다.** `c12`가 이미 `unit II`를 시작해 놓은 것을 발견해 order 13부터 이어갔다. 안 읽었으면 단원을 중복 생성했다.

**발견된 하네스 결함 4건 — 에스컬레이션 6건을 역추적한 결과**

| 에스컬레이션 | 원인 | 결함 여부 |
|---|---|---|
| 2, 3 (기존 팁 oneline 확장) | 판정이 `재사용/신규/표현불가` 3개뿐 | **결함** — 에이전트가 `재사용(조건부)`라는 비표준 값을 지어냈다. 선택지가 없으면 만들어낸다 |
| 1 (교육과정 밖 내용) | 범위 판단 규칙 부재 | **결함** — 에이전트가 스스로 기준을 세워 처리했다 |

**하네스 변경**

- `spec-analyst`: 팁 판정을 **4단계**로 (`재사용 / 기존 확장 / 신규 / 표현불가`). "조건이 붙으면 그것은 기존 확장이다"를 명문화 — 중간값 창작 방지
- `spec-analyst`: **결정 권한 경계표** 추가 (unit/sec 신설, 기존 팁 수정, 교육과정 경계는 사람 승인)
- `spec-analyst`: 교육과정 초과 시 **제외 + 보고** 규칙 (임의 삭제 금지)
- `spec-analyst`: 퀴즈 개념 기본값을 **만들지 않음**으로 (오답 선택지 창작 비용이 개념 본문보다 크다)
- `spec-analyst`: 표현불가 판정에 **영향도(핵심/주변)** 필드 추가 — 형식 확장 판단 근거
- 오케스트레이터: 게이트를 **유형별 차단 범위**로 세분화. 전부 멈추면 승인 불필요한 작업까지 선다

**핵심 교훈**: 에이전트에게 선택지를 3개만 주면 4번째 상황에서 **비표준 값을 창작한다.** 판정 체계는 실제 발생 가능한 경우를 전부 덮어야 한다. 에스컬레이션을 역추적하면 이런 누락이 드러난다.
