**검증된 것 — 회차 0의 두 예측이 실제로 맞았다**

1. **표현불가 에스컬레이션이 실제로 걸렸다.** `derivative`, `naturallog`, `chainrule`, `basechange` 4개가 산점도로 표현 불가 판정되어 파일이 생성되지 않았다. 특히 `naturallog`에 대한 에이전트의 근거가 정확하다 — *"ln n을 억지로 찍으면 발산하는 수열 그림이 되어 학생이 자연로그를 발산 개념으로 오각인한다."* **`build.py`는 이걸 절대 못 잡는다.** 형식만 보기 때문이다. 하네스가 실제로 값을 만든 지점.
2. **기존 자산 실독 규칙이 작동했다.** `c12`가 이미 `unit II`를 시작해 놓은 것을 발견해 order 13부터 이어갔다. 안 읽었으면 단원을 중복 생성했다.

**하네스 변경**

- `spec-analyst`: **결정 권한 경계표** 추가 (unit/sec 신설, 기존 팁 수정, 교육과정 경계는 사람 승인)

## 회차 2 — 개념 작성 및 문서 사실오류 발견 (02:10~02:45)

**한 일**: `concept-author`를 c13/c15/c16에 투입 (opus, 69k 토큰, 2분 28초)

**검증된 것 — 회차 1에서 만든 게이트가 정확히 작동**

요청대로 **차단되지 않은 3개만** 만들고 c14(팁 확장 대기)·c17~c21(sec 신설 대기)은 건드리지 않았다. order 14를 비워 둔 것도 지시대로다. `build.py`는 `euler` 링크 미해결로만 실패했고, 에이전트가 스크래치패드에 사본을 만들어 스텁으로 확인한 결과 **그 외 에러는 없었다**(저장소는 건드리지 않음). 게이트 세분화가 없었으면 9개 전부 멈춰 있었을 것이다.

**발견 — 내 스킬 문서에 사실 오류 5건**

에이전트에게 "규칙이 부족하거나 모호했던 지점을 솔직히 적으라"고 요구한 것에서 전부 나왔다. `build.py` 소스로 **5건 모두 재확인**했다.

| 스킬에 적었던 것 | 실제 | 근거 |
|---|---|---|
| "`lim`/`log`는 자동 로만체" | **`$$` 안에서만**. 본문 `ln a`는 `l`만 이탤릭 | `prose()`가 `\b([A-Za-z])` 단일 문자만 매치 |
| "지수는 `r^n`" | 본문에선 캐럿이 문자 그대로 | `prose()` 정규식이 `_` 첨자만 캡처 |
| "첫 에러에서 멈춘다" | front matter·수식만 즉시 종료. **링크는 누적 후 일괄 보고** | `missing` 리스트에 모아 한 번에 출력 |
| "문단 각 2~4문장" | 기존 c01·c09·c11·c12 **전부 p1이 1문장** | 실측 |
| (누락) | front matter `title`은 변환 안 됨 | `parse_concept`이 원문 반환 |

실제로 c15/c16 title에 `e^x`·`a^x`가 들어가 캐럿이 그대로 노출될 뻔했다. 코퍼스 관례(우리말 제목)에 맞춰 수정했다.

**추가 발견 — 역할 경계 침범**

`spec-analyst`가 인벤토리에 팁의 `curve` 식까지 제안했는데, 이건 `tip-author`의 영역이고 **방향이 틀렸다**(제안한 식은 화면에서 점이 내려가는데, `(1+1/n)^n`은 e로 증가하며 수렴). 상류 제안은 하류에게 근거 없는 앵커로 작동하고, 두 단계를 거쳤으니 검토된 것처럼 보인다 — 실제로는 아무도 안 본 것이다.

**하네스 변경**
- `mathuit-content-format`: **"본문과 수식은 변환 규칙이 다르다"** 대조표 신설 (오류 4건의 뿌리)
- `mathuit-content-format`: 문단 분량을 실측 기반(p1 1~2, p2 2~3)으로 정정, "분량 규칙보다 코퍼스 일관성 우선" 명시
- `mathuit-build-gate`: 종료 방식을 검사 종류별로 구분
- `concept-author`: 표현불가 용어에 뜻을 한 구절 덧붙이는 규칙 (팝업이 없으니 확인할 데가 없다)
- `spec-analyst`: **하류 영역 침범 금지** 절 신설

**핵심 교훈**: 하네스 문서의 사실 오류는 **리뷰로 안 걸린다.** 그럴듯하게 읽히기 때문이다. 실제로 파일을 만들어 보는 에이전트만 발견한다. 그래서 에이전트 프롬프트에 "규칙이 모호했던 지점을 보고하라"를 반드시 넣어야 한다 — 이번 개선의 대부분이 그 항목에서 나왔다.
