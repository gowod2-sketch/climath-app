# 05 · 실전 투입과 개선 루프

**설계만으로는 하네스의 결함이 보이지 않습니다.** 이 스프린트에서 값진 발견은 전부 실제로 산출물을 만들어 본 뒤에 나왔습니다.

---

## 1. 에이전트에게 "규칙이 모호했던 지점"을 요구하라 🟢

**이 한 줄이 개선의 대부분을 만들었습니다.** 모든 에이전트 호출 프롬프트 끝에 넣으세요.

```
반환값에 **규칙이 부족하거나 모호했던 지점**을 솔직히 적으세요.
하네스 개선에 씁니다.
```

산출물만 받으면 이 정보가 사라집니다. 에이전트는 규칙의 빈틈을 메우며 작업하는데, 어떻게 메웠는지 말해주지 않으면 아무도 모릅니다.

실제로 이 항목에서 나온 것: 문서와 실제 도구 동작의 불일치 5건, 룩업 표 오류, 상한 규칙의 오해 여지, 무주공산 축 3개.

## 2. 지적을 곧이곧대로 믿지 말고 소스로 검증하라 🟢

에이전트 지적이 전부 맞지는 않습니다. **맞았다는 것도 확인해야 아는 사실입니다.**

이번엔 지적 5건이 전부 맞았지만, 확인 안 했으면 그것도 몰랐습니다. 반대로 **제가 확인 없이 쓴 것들은 여러 번 틀렸습니다** — 경과 시각을 추정으로 적어 어긋났고, 있지도 않은 순서 함정을 경고했습니다.

**규칙: 도구의 동작을 서술할 때는 소스를 읽고 실제로 실행해 확인한다.**

## 3. 에스컬레이션을 역추적하라 🟢

에스컬레이션은 "사람이 결정할 것"과 "하네스에 빠진 것"이 섞여 있습니다. **역추적하면 후자가 드러납니다.**

첫 실전 투입에서 에스컬레이션 6건 중 **4건이 하네스 결함**이었습니다:

| 에스컬레이션 | 실제 원인 |
|---|---|
| 애매한 판정 2건 | 판정 선택지가 실제 경우를 안 덮음 |
| 범위 초과 항목 | 범위 판단 규칙 부재 |
| 구조 신설 승인 | 권한 경계 미정의 |
| 부가 산출물 생성 여부 | 기본값 미정의 |

각 에스컬레이션에 물으세요 — **"규칙이 있었다면 이게 올라왔을까?"**

## 4. 두 번째 도메인에 프로브를 돌려라 🟢

첫 도메인에서 잘 도는 하네스는 그 도메인에 맞춰 만들었으니 잘 도는 게 당연합니다.

**성격이 다른 두 번째 소재에 분석 단계만** 돌리세요. 파일을 만들지 않으니 싸고, 두 가지가 함께 나옵니다:
- 과적합 여부
- **형식의 진짜 한계** — 첫 도메인에서는 가려져 있던 것

실제로 두 번째 도메인에서야 "산출물이 하나도 성립하지 않는 입력"이 존재한다는 게 보였습니다. 첫 도메인은 비율이 80%여도 기존 자산이 살아남아 문제가 가려져 있었습니다.

## 5. 반복 개정한 뒤에는 반드시 감사하라 🟢

8회차 감사에서 **높음 6건 중 4건**이 *"앞 회차에서 고쳤는데 다른 파일에 옛 서술이 남은"* 유형이었습니다.

가장 위험한 조합: **에이전트 정의와 스킬이 같은 규칙을 각각 적고 있을 때.** 스킬만 고치고 에이전트를 놓치면 에이전트는 옛 규칙을 따릅니다.

감사 항목:
```
[ ] 같은 사실을 두 문서가 다르게 말하는 곳
[ ] 도구 소스와 어긋나는 서술 (소스를 직접 읽고 실행해 대조)
[ ] 룩업 표 전 행 재검산
[ ] 상호 참조 dead link
[ ] 개정 전 상태를 전제로 쓰인 문장
[ ] "충돌 시 X가 우선" 규칙이 있다면 X가 정확한지
```

### 우선순위 규칙이 정정을 되살린다 🟢

*"기존 문서 X와 충돌하면 X가 우선"*이라고 써 두면, **X를 고치지 않는 한 내가 고친 내용이 무효가 됩니다.**

실제로 스킬을 두 번 고쳐놓고, 스킬 스스로 **아직 틀린 문서에 우선권을 주고 있었습니다.** 사람이 읽는 안내서와 에이전트가 읽는 스킬은 갱신 주기가 다릅니다.

### 덤 🟢

이 감사가 하네스 **밖의 실제 앱 버그 2건**까지 찾아냈습니다. 합격선이 exit 0을 내는데도 화면이 깨져 있던 것들입니다. **하네스를 정밀하게 들여다보면 그 하네스가 다루는 시스템의 결함도 같이 보입니다.**

## 개선 루프

```
실전 투입
   ├→ 산출물          → 품질 판단
   ├→ "모호했던 지점"  → 하네스 규칙 보강   ← 여기가 가장 값지다
   └→ 에스컬레이션     → 역추적 → 결함 분리
        ↓
   소스로 검증 → 수정 → 변경 이력 기록
        ↓
   (2~3회차마다) 정합성 감사
```
