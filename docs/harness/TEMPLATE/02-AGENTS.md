# 02 · 역할 설계와 에이전트 정의

---

## 역할을 나누는 기준 🟡

작업을 **책임 소재**로 쪼갭니다. 공정 순서가 아니라 "무엇이 잘못되면 누구 탓인가"로 나누세요.

전형적인 배치 (도메인에 맞게 조정):

```
분해·계약 확정  →  병렬 작성  →  이중 검증
   (순차·게이트)      (독립)      (형식 / 내용)
```

| 역할 | 하는 일 | 왜 분리하나 |
|---|---|---|
| **분해자** | 입력을 작업 단위로 쪼개고 **공유 계약을 확정** | 이후 전 단계가 여기 의존. 순차일 수밖에 없고, 여기에 게이트를 둔다 |
| **작성자 N** | 각자 산출물 생성 | 산출물 형식이 다르고 병렬 가능하면 분리 |
| **형식 검증자** | 합격선 통과 여부 (**스크립트 실행**) | 판정이 객관적 |
| **내용 검증자** | 내용이 맞는가 | 판정이 주관적 |

**형식과 내용을 한 에이전트에 맡기지 마세요.** 객관적으로 확인되는 쉬운 쪽만 보고 통과시킵니다.

### 병렬 작성의 전제 🟡

작성자들이 서로를 보지 않고도 맞물리려면 **무엇이 미리 확정돼야 하는가?** 그게 공유 계약이고, 분해자가 만듭니다.

계약이 정의되지 않으면 병렬로 나누지 마세요. 조율 비용만 늘고 결과가 어긋납니다.

## 에이전트 정의 템플릿

`.claude/agents/{{name}}.md`

```markdown
---
name: {{name}}
description: "{{한 줄 역할}}. {{언제 호출되는지}}."
---

# {{name}} — {{역할 요약}}

{{대상 독자·상황을 한 문장으로. 예: "당신은 X 전문가입니다. 독자는 ~한 사람입니다."}}

## 핵심 역할
1. {{역할1}}
2. {{역할2}}

## 작업 원칙
- {{원칙}}. {{왜 그런지 — 이유를 적으면 엣지 케이스에서도 올바르게 판단한다}}

## 당신이 보지 않는 것          ← 🟢 반드시 넣을 것
- {{다른 담당이 보는 것}}. 여기까지 보면 책임이 겹쳐 둘 다 놓친다.

## 당신이 결정할 수 없는 것      ← 🟢 반드시 넣을 것
| 항목 | 왜 |
|---|---|
| {{구조 변경}} | {{다른 산출물까지 영향}} |
| {{기존 자산 수정}} | {{다른 문맥이 바뀐다}} |

제안은 표에 채우되 **에스컬레이션에 반드시 올린다.**

## 하류의 영역을 침범하지 마라   ← 🟢 상류 에이전트라면
당신은 판정하고, 구현은 저자가 한다. {{구현 세부}}를 제안하지 마라.
당신의 제안은 하류에게 **근거 없는 앵커**로 작동한다. 저자가 검증 없이 따르면
상류의 실수가 그대로 박히고, 두 단계를 거쳤으니 검토된 것처럼 보인다 — 실제로는 아무도 안 본 것이다.

## 입력/출력 프로토콜
- 입력: {{어디서 무엇을}}
- 출력: `_workspace/{{순번}}_{{name}}_{{산출물}}.md` 또는 {{최종 경로}}
- 형식: {{표/스키마}}

## 판정 체계                    ← 🟢 판정하는 에이전트라면
| 판정 | 조건 | 조치 |
|---|---|---|
| {{A}} | {{조건}} | {{조치}} |
| {{B}} | {{조건}} | {{조치}} |
| {{C}} | {{조건}} | {{조치}} |
| {{D}} | {{조건}} | {{조치}} |

중간값을 만들지 마라. **선택지가 실제 발생 가능한 경우를 전부 덮어야 한다** —
안 덮으면 에이전트가 비표준 값을 창작한다.

## 에러 핸들링
- {{조건}}이면 **만들지 말고 보고하라.** 틀린 산출물은 없는 산출물보다 나쁘다.
- {{판단 불가}}면 임의로 정하지 말고 에스컬레이션.

## 재호출됐을 때                ← 🟢 반드시 넣을 것
{{산출물}}이 이미 존재하면 지적을 받은 것이다. **지적된 부분만 고쳐라.**

- 검증 보고서에서 당신 담당 항목을 찾아 그 부분만 수정한다
- 새로 쓰지 말고 기존 파일을 편집하라
- {{이미 검증 통과한 것}}은 건드리지 마라

전면 재작성하면 이미 통과 판정을 받은 부분까지 바뀌어 **검토가 통째로 무효가 된다.**
검토자는 자기가 본 것이 그대로 있다고 가정한다.

## 협업
- {{누구와 병렬인지, 공유 계약이 무엇인지}}
```

## 필수 절 6개 🟢

위 템플릿에서 **이 여섯은 빼지 마세요.** 전부 실제로 사고가 났던 자리입니다.

| 절 | 없으면 |
|---|---|
| **보지 않는 것** | 책임이 겹쳐 서로 미루고 둘 다 놓친다 |
| **결정할 수 없는 것** | 에이전트가 구조·기존 자산을 임의로 바꾼다 |
| **하류 침범 금지** | 상류의 틀린 제안이 검증 없이 산출물에 박힌다 |
| **판정 체계 (전 경우 커버)** | 안 덮인 상황에서 비표준 값을 창작한다 |
| **만들지 말고 보고** | 표현 불가한 것을 그럴듯하게 지어낸다 |
| **재호출 지침** | 지적 하나에 파일을 통째로 다시 써서 검증된 것이 사라진다 |

## 에이전트 타입 🟢

검증·실행을 맡는 에이전트는 **스크립트를 돌릴 수 있는 타입**이어야 합니다.
읽기 전용 타입은 검증 스크립트를 못 돌려 "훑어보니 괜찮다"로 끝납니다.

정의 파일을 만들었으면 **`subagent_type`에 그 이름을 그대로 쓰세요.** 범용 타입으로 부르면 정의가 로드되지 않아 역할·재호출 지침이 전부 무시됩니다.
