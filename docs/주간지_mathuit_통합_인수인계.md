# CLIMATH WEEKLY(에스킬라) → mathuit 통합 — 인수인계

이 파일 하나로 새 세션(통합 전담)이 이어받는다. 아래는 전부 실제 코드를
읽고 확인한 것이다 — 문서만 보고 짐작한 내용은 없다.

**분류(문항 뽑기·유형 나누기·100제 선정·검산·해설 쓰기)는 이 저장소 몫이
아니다.** 그건 `gowod2-sketch/shuttle.plan` 저장소(브랜치
`claude/work-preparation-xpb5nj`)가 계속 맡는다. 여기 climath-app에서는
**mathuit에 주간지를 얹는 기능 개발만** 한다.

---

## 1. 지금 상태 — 결정된 것

| | |
|---|---|
| 통합 여부 | **한다.** mathuit을 "교재 여러 개를 담는 플랫폼"으로 보고, 그 안에 새 교재로 "주간지"(CLIMATH WEEKLY)를 추가한다 |
| 콘텐츠 단위 | **한 페이지 = 한 문항.** mathuit의 기존 방식(좌우로 넘기는 `pages[]` 하나가 화면 하나)을 그대로 따른다 — 3회차를 "펼침면 하나에 문항 여러 개"로 보여주는 방식(아래 4절의 프로토타입)은 **버린다** |
| 로그인 | **공유 비밀번호 2개** (교사용 1개·학생용 1개). 계정별 로그인(Netlify Identity·Supabase Auth)은 안 쓰기로 했다 — 서버·DB 없이 지금 정적 사이트 그대로 유지하는 게 목적 |
| 목차 | mathuit에 **이미 있다** (3절 참고). 새로 만들 것 없이 회차 목록으로 데이터만 바꿔 끼우면 된다 |

## 2. mathuit이 실제로 뭔가 — 코드로 확인한 사실

`mathuit/`은 **"수열의 극한" 개념 하나를 설명하는 단일 흐름 PWA**다.
정적 사이트(`build.py`가 `content/*.md` → `index.html`의
`/*DATA:BEGIN*/.../*DATA:END*/` 블록에 JSON을 주입, Netlify가 push마다
자동 빌드·배포)이지 React 등 프레임워크가 아니다.

- 라이브: mathuit-textbook.netlify.app (Netlify 프로젝트 조회로 확인,
  `ready` 상태) — `mathuit/README.md`에 적힌 옛 도메인
  `math-tip-popup.netlify.app`은 리네임 전 이름으로 보인다
- 편집기: mathuit-editor.netlify.app ↔ `mathuit/editor.html`

### 확인된 기능 (실제 index.html 코드, 문서만이 아니라)

- **필기 — 된다.** `mathuit/index.html`에 진짜 `<canvas class="inkc">`를
  만들어 그리는 코드가 있다. 길게 누르면 필기 모드 진입, 두 손가락으로
  나가기, 토스트 안내("필기 모드 · 두 손가락으로 나가기")까지 구현돼
  있다(대략 800~1090번째 줄 근처, `penOn` 관련 로직).
- **목차(TOC) — 이미 있다.** `.tocpanel`이 슬라이드업으로 뜨고,
  `buildTOC()`가 `pages[]`를 `sec`(구역)별로 묶어 번호·제목을 나열한다.
  항목을 누르면 그 페이지로 점프(`data-go`)하고, 지금 위치를
  `markTOC()`가 표시한다. **주간지의 회차 목록은 이 컴포넌트를 그대로
  쓰면 된다** — `pages[]`를 회차 단위로 채우기만 하면 `sec`이 회차명이
  되어 자동으로 갈린다.
- **퀴즈(문항) 자리 — 있는데 완성이 안 됐다. 이게 핵심 발견이다.**
  - `build.py`의 `parse_concept()`이 프런트매터 `kind: quiz`를 받으면
    `question`·`problemEq`·`options`(1~5)·`answer`를 그대로 페이지
    데이터에 담는다.
  - `editor.html`에는 이 필드들을 편집하는 UI가 이미 있다(문제 모드
    토글, 보기 5개 입력칸, 정답 지정).
  - CSS·상호작용도 있다 — `.quizopt`(보기 클릭), `selectQuizOption()`
    (클릭 시 체크 표시 + 짧은 사운드 피드백).
  - **그런데 실제 페이지를 그리는 함수(`index.html` 약 251번째 줄)에
    `var quiz='';` 로 선언만 해 놓고 그 안을 채우는 코드가 없다.**
    `question`·`options`·정답 표시를 실제 HTML로 만들어 `quiz` 문자열에
    넣는 부분이 통째로 빠져 있어서, 지금 퀴즈 페이지를 열면 제목만 뜨고
    문제·보기가 안 보인다. 예시로 자동 삽입되는 더미 문항(244번째 줄,
    "등비수열의 극한 확인")도 마찬가지로 안 보일 것이다.
  - 이 기능을 만든 커밋은 `2f99d5c`("feat: support direct concept and
    problem page registration", 2026-08-13) — 그 뒤로 더 손댄 흔적이
    없다. **처음부터 새로 만들 게 아니라 이 미완성 기능을 완성하는
    쪽으로 접근하는 걸 추천한다.**
  - 지금 스키마엔 **해설(sol)·출처(src)·모의고사 배지 같은 필드가
    아예 없다** — 주간지에 필요한 만큼 확장해야 한다.
- **인증 — 없다.** `netlify/functions/`엔 편집기 저장을 GitHub 커밋으로
  바꿔주는 함수(`save-content.js`, `GITHUB_TOKEN` 환경변수 사용)만
  있다. 로그인·세션·비밀번호 검사 코드는 전혀 없다. 공유 비밀번호
  방식이면 서버 없이 클라이언트 쪽에서(예: sessionStorage에 검증
  플래그 저장) 간단히 붙일 수 있지만, **그 비밀번호 자체를 어디 어떻게
  저장할지**(정적 사이트라 완전히 숨기긴 어렵다 — 소스에 해시라도
  넣을지, Netlify 환경변수+서버리스 함수로 검증만 서버에서 할지)는
  아직 안 정했다. 새 세션이 정할 것.

### 디자인 규칙 (mathuit/README.md, "바꾸지 말 것")

라이트 모드 고정, 인디고 `#4C5FD5`·바이올렛 `#7B5CE6`·코랄 `#F2653E`·
잉크 `#1B2033`, 수식은 배경 박스 없이 검정 볼드 세리프, 페이지 전환은
슬라이드 340ms(롤링·페이지컬 금지). **주간지 문항 페이지도 이 규칙 안에서
가는 게 자연스럽다** — 3회차 조판/수업판이 쓰는 네이비 `#203F70`·레드
`#D10B35` 배색과는 다른 계열이니, 두 색 체계를 어떻게 조율할지도 정할 것.

## 3. shuttle.plan 쪽 — 통합에 쓸 데이터

- 저장소: `gowod2-sketch/shuttle.plan`, 브랜치
  `claude/work-preparation-xpb5nj`
- 회차 데이터: `round0N/조판/묶음.json` (N=3 조판 준비 끝, 4·5는 분류·
  검산 끝 최근 완성, 1·2는 예전 방식으로 이미 발행됨 — 스키마가 다를 수
  있으니 새로 확인 필요)
- 문항 하나의 필드(3회차 기준): `no`(번호) · `t`(유형 코드) ·
  `body`(발문, `$...$` 안에 raw LaTeX) · `ch`(보기 5개, 역시 raw LaTeX)
  · `ans`(정답, "1"~"5") · `sol`(해설, `\n`으로 단계 구분, raw LaTeX)
  · `d`(난도 점수) · `src`(출처, 예: "휘문고 2026 10번") · `모의`/`모의꼴`
  (기출·기출변형 배지) · `del`(뺀 문항 표시)
- 최상위: `TYPES`(유형 코드→설명), `ORDER`(유형 순서), `LAYOUT`(사람이
  편집기에서 짠 지면 배치 — **한 페이지 한 문항 모델에서는 안 써도
  된다**, 순서만 `ORDER`+유형 안 난도순으로 정하면 됨), `mission`(표지
  문구)
- **수식은 shuttle.plan 쪽도 원본 LaTeX 그대로**(mathuit의 자체
  `mathify()`/`prose()` 변환기와는 다른 방식 — mathuit은 `a_n` 같은
  낱말을 직접 파싱해 이탤릭 처리하고, shuttle.plan은 MathJax가 `$...$`를
  그대로 그리게 한다). **두 렌더러 중 하나로 통일해야 한다** — 문항
  본문을 mathuit의 `mathify()`가 소화 못 할 가능성이 높다(복소수 켤레
  `\overline{}`, 분수 `\frac{}{}` 같은 게 mathuit `SYM` 표에 없다).
  가장 안전한 길은 문항 페이지에서만 MathJax를 쓰는 것 — mathuit이
  라이트 모드·세리프 볼드 규칙을 지키게 MathJax 쪽 폰트만 맞추면 된다.
- 참고용 데이터 생성기: `pipeline/리더_데이터.py` — 묶음.json → 펼침면
  단위 JSON을 뽑는 스크립트(문항 렌더링은 `수업판_만들기.py`의
  `문항들()`을 재사용). **펼침면 모델이라 그대로는 못 쓰지만**, 문항
  하나하나를 안전한 HTML로 바꾸는 부분(`stem_html`의 조건·보기 상자
  가르기)은 그대로 참고할 만하다.
- 프로토타입(참고용, 버리는 방향이지만 화면 감은 참고할 만함): Claude
  Artifact로 낸 "에스킬라 리더" —
  `https://claude.ai/code/artifact/332d6cbb-3c5a-41a5-a511-5296e07f2de2`
  — 펼침면 넘기기 + 문항 탭하면 확대 + 해설 보기 토글. **이 링크 자체는
  mathuit과 무관한 별도 아티팩트이고, "한 페이지 한 문항"으로 방향을
  틀었으니 이 UI 그대로 가져오지 않는다.** 다만 확대 팝업 안에서
  "해설 보기" 누르면 정답이 빨간 테두리로 표시되고 해설이 펼쳐지는
  상호작용은 mathuit 쪽 퀴즈 완성할 때 참고할 만하다.

## 4. 새 세션이 정할 것 (아직 미결)

1. **비밀번호 검증을 어디서 하나** — 완전 클라이언트(소스에 해시만
   심고 비교)면 개발자도구로 우회 가능하지만 서버가 없어도 됨. 서버리스
   함수로 검증하려면 지금 없는 백엔드 조각을 하나 더 얹는 것.
2. **교사/학생 화면 차이** — 로그인만 가르고 화면은 같이 갈지(학생도
   해설을 볼 수 있게), 아니면 학생 화면에서는 "해설 보기" 자체를 숨길지.
3. **수식 렌더러 통일** — mathuit 자체 변환기 vs MathJax, 문항 페이지만
   예외로 둘지 전체를 MathJax로 옮길지.
4. **`quiz` 렌더링 완성** — `index.html`의 빈 `var quiz=''`를 채우는
   작업이 사실상 이번 통합의 핵심 코드 변경이다. 여기에 `sol`·`src`·
   `모의` 필드까지 얹어야 한다.
5. **회차가 여럿일 때 목차 2단 구조** — 지금 TOC는 "구역(sec)별 평면
   목록" 하나뿐이다. "주간지 → 회차 선택 → 그 회차 문항 목록"처럼 한
   단계 더 들어가는 구조가 필요하면 `buildTOC()`를 확장해야 한다.

## 5. 하지 말 것 / 조심할 것

- mathuit은 **라이브 서비스**다(mathuit-textbook.netlify.app). "수열의
  극한" 기존 콘텐츠(개념·팁·필기)를 건드리거나 깨뜨리지 않는 선에서
  작업한다 — `content/concept/`·`content/tip/`의 기존 파일은 그대로
  두고, 주간지는 새 콘텐츠 종류로 옆에 추가하는 방향이 안전하다.
- `index.html`의 `/*DATA:BEGIN*/.../*DATA:END*/` 블록은 `build.py`가
  덮어쓰는 자리다 — 손으로 고치지 않는다(README에도 명시돼 있음).
- `sw.js`(서비스워커) 내용을 고치면 캐시명 `mathtip-vN`을 반드시 올려야
  한다 — 안 그러면 배포해도 사용자 화면이 안 바뀐다.
