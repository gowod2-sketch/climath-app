# 콘텐츠 작성 가이드

앱에 들어가는 **개념**과 **팁개념**은 이 폴더의 `.md` 파일로만 씁니다.
노션은 기획·결정 로그용이고, 실제 콘텐츠는 여기가 원본입니다.

## 폴더 규칙

```
content/
  concept/   개념 (페이지로 넘겨 읽는 본문)
  tip/       팁개념 (용어를 눌렀을 때 뜨는 팝업)
```

파일명이 곧 id입니다. `tip/converge.md` → id `converge`.
id는 영문 소문자로 짓습니다. 개념 본문에서 이 id로 팁개념을 연결합니다.

## 편집기

VS Code, Obsidian, Typora 아무거나 됩니다. 그냥 텍스트 파일입니다.
Obsidian을 이 폴더로 열면 `[[converge]]` 링크가 그래프로 보여서 편합니다.

## 1. 개념 파일 (concept/*.md)

```markdown
---
no: 개념 01
title: 수열의 수렴과 발산
unit: I. 수열의 극한
sec: 01 수열의 극한
order: 1
---

수열 {a_n}에서 n의 값이 한없이 커질 때, 일반항 a_n의 값이 일정한 값 L에
한없이 가까워지면 이 수열은 L에 [[converge|수렴]]한다고 하며,
이때 L을 [[limitvalue|극한값]]이라 한다.

$$ lim_{n->oo} a_n = L $$

수렴하지 않는 수열은 [[diverge|발산]]한다고 하며,
그중 +oo, -oo 어느 쪽으로도 가지 않는 경우를 [[oscillate|진동]]한다고 한다.
```

### 규칙

- 문단은 **수식 앞 / 수식 뒤** 두 덩어리로 씁니다. (앱 레이아웃이 그렇게 생겼습니다)
- `[[id|보이는 글자]]` 가 팁개념 링크입니다. `[[converge|수렴]]` → "수렴"이 파랗게 표시되고 누르면 팝업.
- `$$ ... $$` 안이 수식입니다. 변수는 **자동으로 이탤릭**, `lim` `log` `sin` 숫자 괄호는 자동으로 로만체가 됩니다. 직접 태그 붙일 필요 없습니다.
- 첨자는 `a_n`, 지수는 `r^n` 으로 씁니다.
- 특수기호는 아래 약어를 쓰면 변환됩니다.

| 쓰기 | 나오는 것 |
|------|-----------|
| `->` | → |
| `oo` | ∞ |
| `-oo` | −∞ |
| `<=` `>=` | ≤ ≥ |
| `!=` | ≠ |
| `+-` | ± |
| `sum` | ∑ |
| `...` | ⋯ |
| `alpha` `beta` | α β |

## 2. 팁개념 파일 (tip/*.md)

```markdown
---
title: 수렴
icon: →
oneline: n이 한없이 커질 때 a_n이 한 값에 한없이 가까워짐
related: [limitvalue, diverge]
---

## graph

curve: 60 + 80/n
lines: [60]
label: y = L
label_at: right

## steps

| show | line | label | caption |
|------|------|-------|---------|
| 3  |   |   | a₁, a₂, a₃ 을 순서대로 찍어요. |
| 12 |   |   | n이 커질수록 점들이 한 값으로 몰려가요. |
| 12 | v |   | 다가가는 값을 점선 y = L 로 표시해요. |
| 12 | v | v | a_n은 L에 한없이 가까워져요. |
```

### 그래프 (`## graph`)

그래프는 **n = 1..12 의 점 12개**를 찍는 산점도로 고정입니다.
`curve` 에 화면 y좌표를 만드는 식을 씁니다. **화면 좌표라 값이 작을수록 위쪽**입니다. (10 = 맨 위, 160 = 맨 아래)

| 항목 | 뜻 | 예 |
|------|-----|-----|
| `curve` | n번째 점의 y좌표 식 | `60 + 80/n` (60으로 수렴) |
| `lines` | 점선 보조선의 y좌표 목록 | `[60]` 또는 `[64, 136]` |
| `label` | 보조선 옆에 붙는 설명 | `y = L` |
| `label_at` | 라벨 위치 | `right` `left` `center` |

자주 쓰는 curve 모양:

| 모양 | 식 |
|------|-----|
| 위에서 한 값에 수렴 | `60 + 80/n` |
| 아래에서 한 값에 수렴 | `150 - 90/n` |
| 무한대로 발산 | `152 - 10.5*n` |
| 진동 (두 값 왕복) | `n%2==1 ? 136 : 64` |
| 등비 감쇠 | `150 - 90*0.72**(n-1)` |
| 부분합이 S에 수렴 | `160 - 100*(1 - 0.5**n)` |

### 스토리보드 (`## steps`)

한 줄이 한 스텝입니다. 위에서부터 순서대로, 1초 간격으로 자동 재생됩니다.

| 칸 | 뜻 |
|----|-----|
| `show` | 점을 몇 번째까지 보여줄지 (누적 개수) |
| `line` | 보조선을 켤지. 켜려면 `v` |
| `label` | 라벨을 켤지. 켜려면 `v` |
| `caption` | 그 스텝의 한 줄 설명 (25자 내외) |

스텝은 **2~4개**를 권장합니다. 5개가 넘으면 손을 떼기 전에 다 못 봅니다.

## 3. 고치고 배포하기

### 가장 쉬운 방법 — 웹 편집기

https://math-tip-popup.netlify.app/editor.html

파일을 골라 불러오고, 고치고, **"저장하고 배포"** 를 누르면 끝입니다.
GitHub 커밋이 자동으로 됩니다. 이 폴더를 직접 만질 필요가 없습니다.

다만 **커밋과 배포는 다릅니다.** 편집기는 GitHub에 커밋할 뿐이고, 그것이
화면에 반영되려면 사이트가 git에 연결돼 있어야 합니다.

### 직접 파일을 고쳤다면

```
python3 build.py
```

`content/` 를 읽어 검사하고 `index.html` 안의 `/*DATA:BEGIN*/` 데이터 블록을 갈아끼웁니다.
그 다음 커밋하고 push합니다.

**push가 곧 배포는 아닙니다.** 사이트가 git에 연결돼 있어야 자동 배포가 되고,
연결이 없으면 커밋만 쌓이고 화면은 그대로입니다. 실제로 그런 상태가 12일간
있었습니다. 배포가 됐는지 확인하려면:

```
python3 mathuit/tools/deploy_status.py
```

```
git add -A && git commit -m "개념 수정" && git push
```

문법이 틀리면 빌드가 어디가 틀렸는지 알려주고 멈춥니다. 앱이 깨진 채로 배포되지 않습니다.
이 검사는 Netlify에서도 똑같이 돌기 때문에, 편집기로 저장했더라도 잘못된 내용은 라이브에 나가지 않습니다.
