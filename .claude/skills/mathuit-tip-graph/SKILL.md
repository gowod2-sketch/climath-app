# 팁개념 그래프·스토리보드 설계

팁 팝업에서 그래프를 쓴다면 **n = 1..12 의 점 12개를 찍는 산점도로 고정**이다. 형식을 고를 수 없다.

**`## graph`는 이제 선택이다 (2026-09-05~).** 항등식·식 변형·경우의 수·행렬처럼 수열로 표현되지 않는 개념이 많아, 산점도를 필수로 두면 그런 팁은 아예 못 만들거나 억지로 지어낸 그림이 나갔다. `## graph` 블록을 통째로 생략하면 `build.py`가 `curve: ''`, `nograph: true`로 채우고, 앱은 그래프 없이 `## steps` 캡션만 순서대로 보여준다 (`mathuit/index.html`의 `curveFn`/`openPop`이 `nograph`를 보고 SVG를 아예 안 그린다 — 빈 curve를 넣어 가짜 수평선을 그리던 예전 동작은 버그였고 고쳤다).

**그래프를 뺐다고 스토리보드 규칙이 바뀌진 않는다.** 아래 "스토리보드" 절의 2~4컷·show/line/label/caption 규칙은 그래프가 없을 때도 그대로 적용된다 — 다만 `line`/`label` 칸은 켤 대상(보조선·라벨)이 없으니 항상 비워 둔다. `related`, `syms()` 치환 등 다른 규칙도 동일하다.

## 좌표계가 뒤집혀 있다

`curve`는 수학 값이 아니라 **화면 y좌표**를 만드는 식이다. **값이 작을수록 위쪽**이다.

```
y = 10   ← 화면 맨 위
y = 160  ← 화면 맨 아래
```

그래서 "무한대로 발산"은 값이 커지는 식이 아니라 **작아지는** 식이다. 이 반전을 놓치면 그래프가 위아래 반대로 나오고, 학생은 수렴을 발산으로 배운다.

**검산 방법:** 식에 n=1과 n=12를 대입해 두 값을 비교하라. 의도한 방향인지 눈으로 확인한 뒤 확정한다.

## curve 카탈로그

**표를 읽기 전에:** 아래 "수열의 거동"은 **수학값** 기준이고, "화면"은 **점이 눈에 보이는 방향**이다. 좌표가 반전이라 둘은 항상 반대다 — 값이 커지면 y가 작아지고, 점은 위로 올라간다. 이 표의 값은 실제로 대입해 검산한 것이다.

| 수열의 거동 (수학값) | 식 | y(1) → y(12) | 화면에서 점이 |
|---------------------|-----|-------------|-------------|
| **아래에서** 한 값에 수렴 (증가) | `60 + 80/n` | 140.0 → 66.7 | **위로** 올라가며 y=60에 접근 |
| **위에서** 한 값에 수렴 (감소) | `150 - 90/n` | 60.0 → 142.5 | **아래로** 내려가며 y=150에 접근 |
| +∞로 발산 (계속 증가) | `152 - 10.5*n` | 141.5 → 26.0 | **위로**, 멈추지 않음 |
| 0으로 감쇠 (등비, 감소) | `150 - 90*0.72**(n-1)` | 60.0 → 147.6 | **아래로** |
| 부분합이 S로 수렴 (증가) | `160 - 100*(1-0.5**n)` | 110.0 → 60.0 | **위로** |
| 진동 (두 값 왕복) | `n%2==1 ? 136 : 64` | 136 ↔ 64 | 위아래 반복 |

**"위에서/아래에서 수렴"은 수학값 기준이다.** 극한값보다 **큰 쪽**에서 내려오면 위에서 수렴(감소 수열), **작은 쪽**에서 올라가면 아래에서 수렴(증가 수열)이다. 화면 방향과 헷갈리기 쉬우니 표의 마지막 열까지 같이 읽어라.

**카탈로그를 이름만 보고 고르지 마라.** 고른 뒤 반드시 n=1과 n=12를 직접 대입해 화면 방향이 의도와 맞는지 확인하라. 이 표가 틀렸던 적이 있고, 그때 상류 에이전트가 이름만 믿고 반대 방향 식을 골랐다.

**실제 수열값을 그대로 옮겨도 된다.** 카탈로그는 근사 모양일 뿐이다. 정확한 거동이 중요하면 `362.8 - 111.4*Math.pow(1+1/n, n)` 처럼 실제 수열값의 1차 변환을 써도 좋다 — 극한값이 원하는 y가 되도록 상수를 역산하면 된다. `curve`는 자바스크립트 식으로 평가되므로 `Math.pow`, `**`, 삼항연산자를 쓸 수 있다.

**상수는 화면에 담기게 조절한다.** 대략 10~160 범위에 들어오면 된다. 다만 수렴이 실제로 느린 수열을 억지로 선에 붙이지 마라 — `(1+1/n)^n`은 n=12에서도 2.613이라 e=2.718과 눈에 띄게 떨어져 있고, 그 간격 자체가 사실이다.

## 보조선과 라벨

```
## graph

curve: 60 + 80/n
lines: [60]
label: y = L
label_at: right
```

| 항목 | 뜻 |
|------|-----|
| `lines` | 점선 보조선의 y좌표 목록. `[60]` 또는 `[64, 136]` |
| `label` | 보조선 옆 설명 |
| `label_at` | `right` / `left` / `center` |

## 스토리보드

```
## steps

| show | line | label | caption |
|------|------|-------|---------|
| 3  |   |   | a₁, a₂, a₃ 을 순서대로 찍어요. |
| 12 |   |   | n이 커질수록 점들이 한 값으로 몰려가요. |
| 12 | v |   | 다가가는 값을 점선 y = L 로 표시해요. |
| 12 | v | v | a_n은 L에 한없이 가까워져요. |
```

| 칸 | 뜻 |
|----|-----|
| `show` | 점을 몇 번째까지 보여줄지 (누적 개수, 정수) |
| `line` | 보조선 켜기 — `v` |
| `label` | 라벨 켜기 — `v` |
| `caption` | 그 스텝의 한 줄 설명 (25자 내외, 구어체) |

**2~4컷을 지켜라.** `build.py`가 5개 초과를 거부하고, 1초 간격 자동 재생이라 5컷이면 학생이 손을 떼기 전에 다 못 본다.

**누적으로 쌓아라.** 점 → 점 더하기 → 보조선 → 라벨 순으로 하나씩 켜야 시선이 따라간다. 한 컷에 여러 요소를 동시에 켜면 뭘 봐야 할지 모른다.

## 자잘하지만 걸리는 것들

- **`related`는 실제 존재하는 id만.** 목록을 외우지 말고 `ls mathuit/content/tip/`로 확인하라. 없는 id를 넣으면 빌드가 막힌다.
- **`caption`과 `oneline`에도 기호 치환이 걸린다.** `syms()`는 단어 경계를 보지 않고 통째로 문자열을 바꾼다 — 문장에 `oo`, `sum`, `...`, `alpha`, `beta`가 부분 문자열로 들어가면 조용히 기호가 된다.
- **라벨 y좌표는 `lines[0] - 8`로 자동 배치된다.** 보조선을 화면 위쪽(y ≤ 20)에 두면 라벨이 잘릴 수 있다.
- **스텝은 권장 2~4, 강제 상한 5.** `build.py`는 6개부터 거부하므로 5개도 통과는 한다. 다만 1초 간격 자동 재생이라 5컷은 학생이 손 떼기 전에 다 못 본다 — 통과와 적정은 다르다.

## 산점도로 표현할 수 없는 용어 — `## graph`를 생략하면 된다

이 산점도 형식은 **수열**을 전제한다. 모든 수학 용어가 여기 맞지는 않다.

| 표현 가능 (`## graph` 작성) | 예 |
|----------|-----|
| 극한으로 정의되는 개념 | 자연상수 e — `(1+1/n)^n`의 극한이므로 산점도로 정확히 표현된다 |
| 수렴·발산·진동하는 수열 | 등비수열, 부분합 |

| 표현 불가 (`## graph` 생략) | 예 |
|----------|-----|
| 연속함수의 순간변화율 | 미분계수, 도함수 |
| 각의 항등식 | 삼각함수 덧셈정리, 배각공식 |
| 식 변형·조건 판정 | 인수분해, 나머지정리, 경우의 수, 행렬 연산 |

**표현이 안 되는 용어에 그럴듯한 curve를 지어내지 마라.** 틀린 그림은 없는 그림보다 나쁘다 — 학생이 개념을 시각적으로 잘못 각인한다. `## graph` 블록을 그냥 쓰지 말고, `## steps`만으로 **식이 바뀌어 가는 과정**을 캡션으로 서술하라 (예: 인수분해라면 "전개된 식을 본다" → "공통인수를 찾는다" → "괄호로 묶는다" 같은 2~4컷).

**그래도 에스컬레이션이 필요한 경우는 따로 있다.** 그래프가 아니라 **스텝 캡션조차 2~5컷으로 쪼갤 수 없는 용어**(정의를 한 문장으로만 말할 수 있고 단계적 전개가 없는 경우)를 만나면 팁 파일을 만들지 말고 다음을 보고하라:

1. 용어 id와 스텝으로도 표현이 안 되는 이유
2. 대안 — 팁 대신 개념 본문의 평문으로만 설명할지

`docs/03_지수로그함수_미분.md`, `docs/04_삼각함수_덧셈정리.md`처럼 수열의 극한 단원(concept c01~c11)과 달리 대부분의 용어가 수열이 아닌 단원에서는, 이제 대부분 `## graph` 생략 + `## steps` 서술로 해결된다. 그래도 위 기준에 걸리는 소수 용어만 에스컬레이션하면 된다.
