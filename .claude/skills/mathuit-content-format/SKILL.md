# mathuit 콘텐츠 표기 규칙

`mathuit/build.py`가 강제하는 형식이다. 어기면 빌드가 멈추고 앱이 배포되지 않는다.
`mathuit/content/_README.md`는 사람 편집자를 위한 안내서다. **충돌하면 이 스킬이 우선이다** — `_README`에는 이미 확인된 오류가 남아 있다(curve 표의 "위에서/아래에서 수렴" 행 이름이 뒤바뀜, 본문/수식 변환 차이 미구분). 확신이 안 서면 `_README`가 아니라 `build.py` 소스를 읽어라.

## 개념 파일 — `content/concept/{id}.md`

```markdown
---
no: 개념 01
title: 수열의 수렴과 발산
unit: I. 수열의 극한
sec: 01 수열의 극한
order: 1
---

수열 {a_n}에서 n이 한없이 커질 때 a_n이 일정한 값 L에
한없이 가까워지면 [[converge|수렴]]한다고 한다.

$$ lim_{n->oo} a_n = L $$

수렴하지 않으면 [[diverge|발산]]한다고 하며,
어느 쪽으로도 가지 않으면 [[oscillate|진동]]이라 한다.
```

**필수 키:** `no, title, unit, sec` — 하나라도 없으면 빌드 실패. `order`는 선택(기본 999).

**수식은 정확히 1개.** 앱이 `$$ ... $$` 앞을 p1, 뒤를 p2로 잘라 두 영역에 렌더하기 때문이다. 그래서:
- 수식을 문장 중간에 끼워 넣으면 앞뒤 문단이 문장 조각으로 잘린다
- 공식이 2개면 개념을 2개로 쪼개야 한다 — 억지로 한 파일에 넣지 마라
- 앞뒤 문단은 각각 독립적으로 읽혀야 한다

**분량은 p1 1~2문장, p2 2~3문장.** 기존 `c01`·`c09`·`c11`·`c12` 전부 p1이 1문장이다. 수식 앞은 "무엇을 볼 것인가"를 한 문장으로 세우고, 뒤에서 조건과 예외를 붙이는 구조다. 새로 쓸 때 기존 파일을 먼저 열어 어투를 확인하라 — 분량 규칙보다 코퍼스 일관성이 우선이다.

**퀴즈 변형:** `kind: quiz`를 넣으면 본문 대신 front matter의 `question, problemEq, option1`~`option5`, `answer`(정답 번호)를 읽는다. 이때는 `$$` 수식이 필요 없다.

## 팁개념 파일 — `content/tip/{id}.md`

**필수 키:** `title, oneline` (선택: `icon`, `related`)
**필수 블록:** `## graph`와 `## steps` — 둘 다 없으면 빌드 실패

그래프와 스토리보드 설계는 별도 스킬 `mathuit-tip-graph`를 참조하라.

## 팁 링크 — `[[id|보이는 글자]]`

`[[converge|수렴]]` → "수렴"이 파랗게 표시되고 누르면 팝업이 뜬다.

**id는 반드시 실제 `tip/{id}.md` 파일이어야 한다.** 하나라도 없으면 빌드가 멈춘다. 이 실패는 파일을 하나씩 봐서는 보이지 않으니, 링크 목록과 파일 목록을 동시에 놓고 대조하라.

파일명이 곧 id다. 영문 소문자로 짓는다.

## 기호 약어

유니코드를 직접 입력하지 마라. 변환기가 처리한다.

| 쓰기 | 나오는 것 | | 쓰기 | 나오는 것 |
|------|-----------|-|------|-----------|
| `->` | → | | `sum` | ∑ |
| `oo` | ∞ | | `...` | ⋯ |
| `-oo` | −∞ | | `alpha` `beta` | α β |
| `<=` `>=` | ≤ ≥ | | `!=` | ≠ |
| `+-` | ± | | | |

## 본문과 수식은 변환 규칙이 다르다 — 가장 자주 틀리는 지점

`$$ ... $$` 안은 `mathify()`가, 본문은 `prose()`가 처리하는데 **둘의 능력이 다르다.** 수식에서 되는 것이 본문에서는 안 된다.

| 표기 | `$$` 안 | 본문 |
|------|---------|------|
| 기호 약어 (`->` `oo` `sum`) | **깨진다 — 아래 참조** | 변환됨 |
| 첨자 `a_n` | 아래첨자 | 아래첨자 |
| **지수 `a^x`** | 위첨자 | **캐럿 그대로 뜬다** |
| **함수명 `lim` `log` `ln` `sin`** | 로만체 | **깨진다 — 아래 참조** |
| 단일 변수 `a`, `x` | 이탤릭 | 이탤릭 |

**본문에서 `ln`, `log`, `sin` 같은 함수명을 쓰지 마라.** `prose()`는 **한 글자** 라틴 문자만 이탤릭 처리하므로, `ln a`는 `l`만 이탤릭이 되고 `n`은 평문으로 남아 글자가 따로 논다. 함수명이 필요하면 수식 안에 넣거나, 본문에서는 우리말로 풀어 쓴다 — `ln a` 대신 "밑 a의 자연로그".

**본문의 지수는 캐럿이 그대로 보인다.** 기존 `c12`도 본문에 `y = a^x`를 그대로 쓰고 있다. 관례를 따르되, 지수가 의미의 핵심이면 수식 쪽으로 옮기는 편이 낫다.

**`$$` 안에서는 기호 약어를 쓰지 마라 — 오히려 깨진다.** `mathify()`가 `syms()`가 만든 HTML 엔티티(`&#8721;`)를 문자 단위로 쪼개 각각 span으로 감싸기 때문에, 화면에 `&#8721;`이 글자 그대로 나온다. 이미 개념 03·06·07·08·10의 수식에 이 파손이 출고돼 있다. 수식 안에서는 `sum` 대신 문제를 우회하거나, 필요한 기호를 본문 쪽에 두어라.

**팁 링크 id에 `sum`·`oo`·`alpha`·`beta`·`...`가 들어가면 링크가 조용히 죽는다.** `prose()`가 링크를 파싱하기 **전에** `syms()`를 돌리므로, `[[sumval|급수의 합]]`은 `[[&#8721;val|…]]`이 되어 링크 정규식에 걸리지 않는다. 결과적으로 화면에 `[[∑val|급수의 합]]`이 대괄호째 노출되고 팝업이 뜨지 않는다.

**그리고 `build.py`는 이걸 잡지 못한다** — 링크가 아예 생성되지 않아 "없는 팁 id" 검사에도 걸리지 않고 exit 0을 낸다. 기존 `sumval` 팁이 정확히 이 문제를 겪고 있다(개념 03·04). 새 팁 id를 지을 때 `SYM` 테이블의 문자열을 부분 문자열로 포함하지 마라.

**`syms()`는 무조건 문자열 치환이다.** 본문 어디든 `oo`, `sum`, `...`, `alpha`, `beta`가 **부분 문자열로만 들어가도 조용히 기호로 바뀐다.** 영어 단어나 고유명사를 본문에 쓸 때 주의하라.

**front matter의 `title`은 변환을 타지 않는다.** `title: 지수함수 e^x의 미분`이라고 쓰면 화면에 `e^x`가 문자 그대로 나온다. 제목에는 수식 표기를 넣지 말고 우리말로 쓴다 — "지수함수의 미분".

**수식에 서식 태그를 붙이지 마라.** `$$` 안에서는 변수 이탤릭과 `lim`/`log`/`sin`/숫자/괄호의 로만체가 자동 적용된다. 직접 지정하면 이중 적용된다.

## 검증

```bash
cd mathuit && python3 build.py
```

통과해야 배포된다. 이 검사는 Netlify에서도 동일하게 돌기 때문에, 웹 편집기로 저장했더라도 잘못된 내용은 라이브에 나가지 않는다.
