# mathuit 앱 화면 점검

`build.py` 는 형식을, `check.py` 는 데이터를 본다. **그려진 화면은 아무도 안 본다.**
이 절차가 그 층이다.

실제로 이 층이 없어서 놓친 것들:
- 팁 링크가 죽어 `[[∑val|급수의 합]]` 이 대괄호째 3주 넘게 라이브에 있었다
- 수식의 `∑` 자리에 `&#8721;` 이 글자로 나왔다
- 콘텐츠에 없는 **하드코딩 퀴즈**가 개념 사이에 끼어 나갔다

## 실행

```bash
cd mathuit
python3 tools/shoot.py              # 화면 순서 확인 (캡처 없음)
python3 tools/shoot.py 3 7 13       # 해당 인덱스 캡처
python3 tools/shoot.py --all        # 전부
```

출력은 `mathuit/tools/_shots/pNN.png`. **반드시 이미지를 열어서 보라** — 파손 자동 판정은 보조일 뿐이고, 레이아웃 문제는 눈으로만 보인다.

## 인덱스가 `content-data.json` 과 다르다

`index.html` 은 콘텐츠에 퀴즈가 하나도 없으면 **샘플 퀴즈를 3번째 자리에 강제로 끼워 넣는다**(`PAGES.splice(2, 0, ...)`). 그래서 화면 순서가 파일 순서와 어긋난다.

`tools/shoot.py` 를 인자 없이 돌리면 이 하드코딩분을 포함한 **실제 화면 순서**를 보여준다. 목차 index 를 직접 계산하지 말고 그 목록을 쓰라.

## 자동으로 표시되는 것

캡처할 때 각 화면을 검사해 `⚠` 로 표시한다.

| 표시 | 뜻 |
|------|-----|
| `죽은링크` | 본문에 `[[` 가 남아 있다 — 링크가 생성조차 안 됐다 |
| `엔티티노출` | `&#8721;` `&minus;` 가 글자로 보인다 |
| `헤더잘림` | 단원명이 길어 `sec` 이 `...` 로 잘렸다 |

**표시가 없다고 정상은 아니다.** 이건 알려진 파손 3종만 본다.

## 눈으로 확인할 것

- **긴 단원명** — `II. 지수함수와 로그함수의 미분` 처럼 길면 헤더가 깨지고 "앱 설치" 버튼이 세로로 쪼개진다. `I. 수열의 극한` 처럼 짧으면 멀쩡하다. 새 단원을 넣을 때마다 확인하라.
- **본문의 지수** — `a^x` 는 본문에서 캐럿이 그대로 보인다(알려진 제약). 수식 안에서는 정상이다.
- **스텝 연출** — 팁 팝업의 요소가 한 컷씩 켜지는지.

## 뷰포트가 500px 아래로 안 내려간다

헤드리스 크롬은 창 폭을 500 미만으로 만들지 못한다. `--window-size=390` 을 줘도 **`window.innerWidth` 는 500** 이 되고 이미지만 390 으로 잘린다.

이걸 모르면 **잘린 이미지를 앱의 반응형 버그로 오해한다**(실제로 그렇게 오해한 적이 있다). `shoot.py` 는 500 을 하한으로 쓴다. 더 좁은 화면을 봐야 하면 실기기나 다른 도구가 필요하다.

## 크롬을 못 찾을 때

`shoot.py` 의 `CHROME_CANDIDATES` 에 경로를 추가하라. Playwright 는 npm·pip 가 막힌 환경이 있어 의존하지 않는다 — 크롬 바이너리만 있으면 된다.
