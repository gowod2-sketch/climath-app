# mathuit 빌드 검증

`build.py`는 배포 게이트다. 실패하면 Netlify 빌드도 같은 지점에서 멈추므로 깨진 앱이 라이브로 나가지 않는다.

```bash
cd mathuit && python3 build.py
```

## 합격선

| 대상 | 조건 | 실패 메시지 |
|------|------|-----------|
| front matter | `---`로 시작하고 `---`로 닫힘 | `맨 위에 --- 로 시작하는 설정 블록이 필요합니다` |
| front matter | `키: 값` 형식 | `설정은 "키: 값" 형식이어야 합니다` |
| concept | `no, title, unit, sec` 존재 | `{키} 가 없습니다` |
| concept | `$$ 수식 $$` 존재 | `$$ 수식 $$ 이 없습니다` |
| tip | `title, oneline` 존재 | `{키} 가 없습니다` |
| tip | `## graph` 블록 존재 | `## graph 블록이 없습니다` |
| tip | `## steps` 블록 존재 | `## steps 블록이 없습니다` |
| steps | `show` 칸이 정수 | `show 칸은 숫자여야 합니다` |
| steps | 1줄 이상 | `스텝이 한 줄도 없습니다` |
| steps | **5줄 이하** | `스텝은 5개까지만 (지금 N개)` |
| 링크 | 모든 `[[id\|...]]`에 `tip/{id}.md` 존재 | `연결된 팁개념 파일이 없습니다` |

`kind: quiz` 개념은 `$$` 수식 검사를 건너뛴다.

## 한 번 통과가 전부 깨끗하다는 뜻은 아니다

`build.py`의 종료 방식은 검사 종류에 따라 다르다. 이걸 구분해야 몇 번 돌려야 하는지 안다.

| 검사 | 종료 방식 |
|------|----------|
| front matter · 수식 · graph/steps 블록 | **첫 에러에서 즉시** `sys.exit(1)`. 뒤의 에러는 보이지도 않는다 |
| 팁 링크 정합성 | 전체 파일을 다 읽고 **누락분을 한꺼번에** 출력한 뒤 종료 |

따라서 링크 에러가 5줄 나왔다면 그 5개가 링크 문제의 전부다. 하지만 그 앞 단계에서 파일 하나가 걸리면 링크 검증까지 도달하지도 못한다.

**고친 뒤 반드시 재실행하라.** 통과가 나올 때까지 반복한다. 한 번 고치고 "됐다"고 넘어가면 다음 사람이 두 번째 에러를 받는다.

## 링크 정합성은 따로 봐야 한다

파일이 각각 멀쩡해도 concept의 링크 id와 tip 파일명이 어긋나면 실패한다. 이 불일치는 **파일을 하나씩 읽어서는 보이지 않는다.** 양쪽 목록을 뽑아 차집합을 구하라:

```bash
cd mathuit
grep -rhoE '\[\[[a-z0-9_]+' content/concept/ | sed 's/^\[\[//' | sort -u > /tmp/used.txt
ls content/tip/ | sed 's/\.md$//' | sort -u > /tmp/exist.txt
comm -23 /tmp/used.txt /tmp/exist.txt   # 링크했는데 파일 없음 → 빌드 실패 원인
comm -13 /tmp/used.txt /tmp/exist.txt   # 파일은 있는데 아무도 안 씀 → 고아 팁
```

## 빌드가 강제하지 않는 규약도 대조하라

`build.py`를 통과했다고 규약을 지킨 것은 아니다. 아래는 빌드가 보지 않지만 어긋나면 실제로 잘못된 앱이 나가는 항목이다.

**먼저 범위를 좁혀라.** 기존 콘텐츠에는 이미 규약을 벗어난 파일이 많다(예: 스텝 점등 규약은 기존 팁 22개 중 14개가 위반). 전체를 훑으면 매번 같은 줄이 쏟아져 **노이즈가 실제 위반을 덮는다.** 이번 작업이 만들거나 고친 파일만 본다:

```bash
cd /home/user/climath-app
git diff --name-only HEAD -- mathuit/content/ ; git ls-files -o --exclude-standard mathuit/content/
```

### 1. 인벤토리 대 생성물 누락 대조

가장 중요하다. 계획된 개념이 빠지면 **다른 개념의 근거가 사라진다.** order 공백은 "번호가 비었다"로 보이지만 실제 문제는 "그 공식을 참조하는 개념이 순환 서술이 됐다"이다.

인벤토리에는 맥락으로 언급된 기존 파일도 섞이므로, **"## 개념 목록" 표의 행에서만** 뽑아야 한다. 반대 방향(파일은 있는데 계획에 없음)은 기존 콘텐츠가 전부 걸리니 보지 마라.

```bash
cd /home/user/climath-app
# 인벤토리의 "## 개념 목록" 표 행에서만 파일명 추출
awk '/^## 개념 목록/{f=1;next} /^## /{f=0} f && /^\|/' _workspace/01_*_inventory.md \
  | grep -oE 'c[0-9]+\.md' | sort -u > /tmp/planned.txt
ls mathuit/content/concept/ | sort -u > /tmp/made.txt
comm -23 /tmp/planned.txt /tmp/made.txt   # 계획됐는데 없음 ← 이 방향만 본다
```

빠진 파일이 **의도된 보류**(승인 대기)인지 **사고**인지 구분해 보고하라. 판별 근거: 보류 사유가 인벤토리 에스컬레이션에 있는가, 그리고 보류가 일관되게 지켜졌는가(미승인 `sec` 값이 콘텐츠에 몰래 들어가지 않았는가).

### 2. 근거 사슬 추적 — 보류가 남긴 구멍

보류된 개념에 **의존하는 출고 개념**이 있으면 그 개념은 순환 서술이 된다. 이 의존은 `[[id]]` 링크가 아니라 **평문 문장에 숨어 있어 grep으로 잡히지 않는다.**

절차: 인벤토리 "## 개념 목록" 표의 **수식 열**을 보류된 개념들에 대해 뽑고, 출고된 개념 본문이 그 수식의 결과를 **근거로 인용하는지** 읽어라. "~이기 때문이다", "~가 1이 되므로" 같은 문장이 신호다.

예: 출고된 개념이 "남은 극한이 1이 되기 때문이다"라고 쓰는데 그 극한을 다루는 개념이 보류됐다면, 왜 1인지 답할 화면이 앱에 없다.

**보류 단위는 개념 하나가 아니라 근거 사슬이어야 한다.** 발견하면 해당 개념도 함께 보류할 것을 제안하라.

### 3. 중첩 사각지대 — 각각은 옳은데 겹치면 구멍

개별로는 정당한 결정 둘이 겹치면서 **어떤 용어를 설명하는 화면이 하나도 안 남는** 경우가 있다. 팁은 표현불가로 미생성, 그 용어를 다루는 개념은 보류 — 둘 다 맞는 결정이지만 결과적으로 학생이 그 말을 어디서도 확인할 수 없다.

출고 본문의 평문 전문용어를 뽑아, **팁도 없고 그 용어를 다루는 개념도 없는 것**을 찾아 보고하라. 인벤토리가 예상하지 못하는 종류의 구멍이다.

### 4. 그 밖의 규약 점검 (신규·변경 파일만)

| 항목 | 확인 |
|------|------|
| `title`이 인벤토리와 일치 | 다르면 어느 쪽이 옳은지 판단하라. front matter는 변환을 타지 않으므로 **제목에 수식 표기가 있으면 인벤토리 쪽이 틀린 것**이다 |
| `title`에 수식 표기 없음 | `e^x`가 캐럿째 노출된다 |
| 스텝이 요소를 하나씩 켬 | 신규 팁만. 기존 팁 대부분이 위반이라 전체를 보면 무의미하다 |
| `order` 연속성 | 공백이 있으면 위 누락 대조로 원인 확인 |

이 항목들은 **차단이 아니라 보고**다. 판단은 사람이 한다.

## index.html이 함께 바뀐다

`build.py`는 검사만 하는 게 아니라 `index.html` 안의 `/*DATA:BEGIN*/` 데이터 블록을 갈아끼운다. 검증 목적으로 돌려도 **`index.html`이 수정된다.**

`git status`로 확인하고, 콘텐츠 변경과 함께 커밋할 것인지 판단하라. 내용이 동일하면 `주입: 변경 없음`이 출력되고 파일은 건드리지 않는다.

## 실패 보고 형식

원문을 그대로 옮기지 말고 담당까지 지정해서 넘겨라.

| 파일 | 에러 원문 | 해석 | 담당 |
|------|----------|------|------|
| `tip/deriv.md` | `스텝은 5개까지만 (지금 6개)` | 스토리보드 1컷 삭제 필요 | tip-author |
| `concept/c13.md` | `연결된 팁개념 파일이 없습니다` | `[[natlog]]` 링크의 tip 파일 부재 | tip-author 또는 링크 제거 |
