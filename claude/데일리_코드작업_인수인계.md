## 3. 코드 구조

단일 HTML 안에 원본 + 애드온이 층으로 쌓인 구조. **원본은 건드리지 않고 블록만 얹는다. 블록을 지우면 이전 버전으로 완전 복귀되어야 한다.**

```
index.html
├─ 원본 (CLIMATH 데일리 현황)  ─ supabase-js CDN + 인라인 <script>
├─ <style id="v4skin">          ─ 스킨(색) 덮어쓰기
├─ <script id="na-addon">       ─ 다음 액션 애드온 (R0~R7 규칙엔진, IIFE)
├─ <style id="v43skin">         ─ 상담기록 스킨
└─ <script id="v43addon">       ─ 상담기록 아코디언
```

### 주요 함수 (원본)
`render` · `fetchAllStudents` · `fetchAttendance` · `upsertAttendance` ·
`resolveStudentName` · `makeDisambigKey` · `scheduleForDate` · `subscribeRealtime` · `initApp`
`renderMessageView` · `openHomeworkPrompt` · `tierOf`

### DOM
```
.student-card
  .card-hdr
    .avatar
    .card-info > .card-name      ← 여기에 '액션' 버튼이 주입됨
    .card-right                  ← att-toggle, reason-btn, hw-badge, arr-sel, sched-badge, arrow, del-btn
  .card-body > .sched-row
```
하단 FAB: `⬇ 앱 설치` · `📅 주간출석` · `📋 출석부` · `📂 진도CSV·JSON(복수)`
상단: 새로고침 · 조치필요 학생 · 다크모드 · 날짜 이동(‹ 오늘 ›) · 출석현황 · 💬 문자미리보기 · 보강

### 애드온 구현 함정 (반복해서 밟는 것)
- 원본 애드온이 IIFE라 `bodyHTML`을 밖에서 못 건드린다 → `#naBody` **MutationObserver** 로 주입.
- 오버레이는 '액션' 첫 클릭의 **동기 블럭 안**에서 생성되고 바로 innerHTML이 채워진다. 옵저버 콜백은 이미 늦다.
  → 옵저버 부착 직후 `if (body.children.length) run()` 을 한 번 직접 호출해야 **첫 열기**에서 뜬다.
- 다크 모드: `body.dark-mode` 가 `:root` 보다 특이도가 높다. `:root` 만 덮으면 다크에서 금지색(초록)이 되살아난다.

## 4. DB 스키마

**`students`** — `name`(키, 동명이인은 `이서현a`/`이서현b`) · `school` · `grade` · `ban`(예 `개진반_월수금`) · `note` · `default_arrival`(jsonb, 요일별) · `progress`(jsonb)

```json
progress: [{"date":"7월 21일","slots":[{"lv":"3-2","sub":"기본","cnt":"1단원"}]}]
```

**`attendance`** — `student_name` + `date`(**`"7/24"` 형식, 연도 없음**) 가 **PK**.
`present`(bool) · `arrival`(int) · `reason` · `homework` · `test_score` · `hw_rate` ·
`video_url` · `video_sent_at` · `makeup_decision` · `makeup_date` · `date_iso`(트리거 생성)

> PK가 `(student_name, "date")` 여야 supabase-js `.upsert()` 가 동작한다. **변경 금지.**

**`action_log`** — `id`(bigint) · `student_name`(**`student_id` 아님**) · `created_at` · `action_type` · `rule_id` · `title` · `memo` · `due_date`(date) · `status`(현재 전부 `open`). `created_by` 컬럼은 **없다.** 팝업 "과거 액션 이력"의 저장소.

**`consult_calls`** — `id, student_name, called_at, drive_file_id, file_name, phone, bytes, approx_min, transcript, summary, action_hint, category, created_at`
현재 **204건 / 959분 / 38명**, `transcript`·`summary` 각 **155건(76%)**. 남은 전사 49건. (2026-09-04 라이브 조회 실측 — 아래 §11)
미승인 변경: `alter table consult_calls add column topic text;`

**리얼타임**: `supabase_realtime` 퍼블리케이션에 `students`·`attendance` 가 들어 있어야 `subscribeRealtime()` 이 산다.

## 6. 배포 절차

1. `version.json` 의 `build` 와 `<html data-build="...">` 를 **같은 값**으로 갱신. 형식 `YYYY-MM-DD_HHMM` (KST). 안 바꾸면 업데이트 배너가 안 뜬다.
2. 스테이징에 먼저 올려 원장 확인. **운영 반영은 원장 승인 후.**
3. Netlify **Deploys 페이지에서 zip drop**.
   - Netlify MCP `deploy-site` 는 egress 차단으로 403 → 안 됨.
   - Chrome 확장으로: sr-only 파일 input `#dropzone-file-upload` 을 CSS로 노출 → `file_upload` 로 zip 투입. 폴더 input 은 숨겨야 오인식이 없다.
4. 배포 즉시 `next-action-site\` 에 zip 커밋.
5. 롤백: Netlify Deploys → 직전 배포 Publish.

### 환경 제약
- 클라우드 컨테이너도 원장 PC VM(`device_bash`)도 **아웃바운드 화이트리스트**. `netlify.app`·`supabase.co` 에 curl 직접 불가 → 브라우저(Chrome 확장) 경유.
- 아티팩트 페이지는 CSP로 외부 `fetch` 가 차단된다. 다만 **라이브 연결은 가능하다** — `fetch` 가 아니라 아티팩트 런타임의 `mcp` 기능으로 claude.ai **Supabase 커넥터**를 호출하면 CSP를 타지 않는다. 통합 허브 `CLIMATH 데일리운영` 탭이 이 방식으로 돌고 있다 (2026-09-04 적용). 발행 시 `capabilities: {"mcp":{"servers":[{"server":"Supabase","tools":["execute_sql"]}]}}` 와 `contract 0.2.41` 이상이 필요하다.
- Netlify SPA 폴백 때문에 없는 파일도 200 + index.html 이 온다. 응답 앞이 `<!doctype html>` 이면 버릴 것.

## 7. 작업 원칙 (원장 확정)

- **디벨롭한다. 새로 만들지 않는다.** 기준은 운영 중인 `CLIMATH 데일리 현황`.
- **앱으로 기록하고, 시트에서 종결한다.** 앱→시트는 **빈 칸만**. 값이 있으면 원장 확정분이므로 덮지 않는다. 다르면 목록으로 보고.
- **판단 근거를 항상 같이 보여준다.** 규칙에 R번호를 달아 역추적 가능하게.
- 데이터가 얇아 부정확하면 **추천하지 말고 보류**.
- **초록은 쓰지 않는다.** 미드나잇 네이비 `#10142a`/`#1b2140` + 앰버 `#f5a524`. 앰버 배경 위 글씨는 네이비 `#141833`(흰색은 대비 2:1로 안 읽힘). 라이트/다크 **양쪽** 확인.
- 비밀번호·API 키는 Claude 가 다루지 않는다. Supabase SQL 실행·키 발급은 원장이 한다.
- 설명보다 실물. 반말, 간결하게.

### 출석부 칸 배정
| 서버 | 칸 | 값 |
|---|---|---|
| 출석 | 출결 | `O` |
| 결석 | 출결 | `/` |
| 지각 | 출결 | `△` |
| 결석 사유 | 과제 | 텍스트 (**빈 칸일 때만**) |
| 보강 배정 | 오답 | `8/25` |

출석부 코드: `정` 예정 · `보` 보강 · `T` 테스트 · `모` 모의고사 · `직` 직전보강 · `실1/실2` 실전
시트 함정: 한 탭에 월 블록이 가로로 이어지고 블록마다 명단이 다르다. CSV export 는 첫 시트만 → **탭 전체 순회 필요.**
동명이인(`이서현` 3명, `남보석`·`김규원` 각 2명) → 이름 매칭은 반드시 깨진다. 학생 ID + 학부모 번호로 잡을 것.
